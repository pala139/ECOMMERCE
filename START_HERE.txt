🔐 AUTHENTICATION FLOW
═════════════════════════════════════════════════════════════════════════════════

1. USER REGISTERS
   Client sends credentials
   ↓
   AuthService validates & hashes password
   ↓
   User saved to database
   ↓
   JWT token generated
   ↓
   Return token to client

2. USER LOGS IN
   Client sends email & password
   ↓
   AuthService validates credentials
   ↓
   Password comparison with BCrypt hash
   ↓
   JWT token generated
   ↓
   Return token to client

3. CLIENT MAKES REQUEST
   Client sends Authorization: Bearer <token>
   ↓
   JwtAuthenticationFilter validates token
   ↓
   Extracts email from token
   ↓
   Sets in SecurityContext
   ↓
   Controller receives authenticated user
   ↓
   Request processed with user info

   Stateless security

✅ Single Responsibility Principle
   Each class has one reason to change

🎓 INTERVIEW TALKING POINTS
═════════════════════════════════════════════════════════════════════════════════

Architecture
└─ "Layered architecture separates concerns: entities handle data structure,
   repositories handle access, services handle logic, controllers handle HTTP"

Authentication
└─ "JWT provides stateless authentication - token contains user info signed
   with secret, server validates without database lookup, scales horizontally"

Database
└─ "JPA/Hibernate eliminates boilerplate - entities map to tables, repositories
   provide type-safe queries, no raw SQL needed"

API Design
└─ "DTOs decouple API from database - if database changes, API stays stable,
   clients don't break when we evolve the system"

Testing
└─ "Clean architecture makes testing easy - services can be tested independently
   by mocking repositories, controllers tested with mock services"

Scalability
└─ "To scale: add database replicas for reads, cache products in Redis,
   queue orders in RabbitMQ, split into microservices, load balance with Nginx"
